# 发布说明

本文说明本次开源整理的**范围、排除项、验证方法与未验证事项**。
目的是让阅读者能够判断：这个仓库里有什么、没有什么、哪些结论有证据、哪些没有。

| 项 | 值 |
|---|---|
| 来源 | 作者本地的 IAR 工程工作区 |
| 基线提交（`main` 分支） | `fc4a8c5` |
| 基线提交（`feature/adaptive-find-lines` 分支） | `0a5d30f` |

两个分支各自以**单个提交**的形式发布，不携带原始开发历史。

### 1.1 为什么切断历史

原始开发历史中包含以下内容，均不适合随公开仓库发布：

| 内容 | 说明 |
|---|---|
| `project/doc/` 下的两份个人文档 | 已决定不公开（见 §2），但它们存在于历史中，保留历史即等于公开 |
| `project/iar/Debug_m4/` 下的构建产物 | 数百个目标文件与 browse 数据库，跨多次提交累积 |
| IAR 个人会话文件 | 含构建机的绝对路径 |
| 口语化的提交信息 | 例如「推送测试，无修改」「fix」「临时修改，测试电机是否正常」 |

以快照形式发布可以把上述内容一次性排除干净。

### 1.2 代价

- 无法通过 git 追溯到每一次改动的动机
- 无法 `git blame` 定位某行代码的引入时间

若需要完整历史，请向作者索取。

## 3. 验证方法与结果

由于本机没有可用的 IAR 工具链，无法通过编译来验证。因此改用**可证伪的静态检查**。
以下每项都在整理过程中实际执行过。

### V1 自研源码零改动

对 `project/user/main_cm4.c` 与 `project/user/cm4_isr.c` 计算
「去块注释 → 去行注释 → 去全部空白 → SHA256 取前 16 位」的指纹，
比对源工程工作区与公开树。

**结果**：两个分支各 2/2 文件指纹一致。即整理过程**没有改动任何一行自研代码**。

### V2 第三方库字节校验

对 `libraries/` 下每个文件做 SHA256 比对。

**结果**：除 §2.2 中的两个恢复文件与新增的 `libraries/LICENSE` 外，
全部文件与源工程逐字节一致。

### V3 排除项检查

遍历公开树的全部路径。

**结果**：`project/iar/Debug_m4/`、`project/iar/settings/`、
`project/iar/project_config/settings/`、`project/doc/` 均**零命中**；
且 `libraries/doc/` 未被误删。

### V4 凭据扫描

对全部 git 对象（含历史）与工作区文件扫描：WiFi 口令、SSID、API key、
私钥、邮箱、手机号、已知的口令字面量。

**结果**：**零命中**。仓库中唯一出现的 IP 地址位于第三方 FreeRTOS+TCP 源码的示例配置中。

### V5 快照结构

**结果**：每个分支恰好 1 个提交，且为无父提交的孤立提交。

### V6 编码检查

**结果**：公开树中 `project/user/*.c` 为 UTF-8，逐飞库为 GBK，
**无 U+FFFD**、**无异常 `?` 连续串**（个别 `?` 为 C 语言三目运算符）。
保留的 `?` 全部位于 `zf_device_imu660ra.h`、`imu660rb.h`、`imu963ra.h`、`ips200.h`
的 `CS(x)` / `RD(x)` 宏中。

### V7 数字可回溯

README 与 `docs/` 中出现的每个数值，均标注了其在源码中的行号或宏名。
逐项核对过与源码一致。

> 未做的一项：**没有编译，也没有实车验证**。见 §4。

## 4. 未验证事项（重要）

以下结论**在本仓库中不成立**，请不要据此推断：

| 未验证项 | 说明 |
|---|---|
| **能否编译** | IAR 是仅图形界面的商业工具链，本次整理未在 IDE 中执行编译。仓库中不含任何 `.out` / `.hex` / `.map` 文件 |
| **能否在硬件上运行** | 无烧录与上电记录 |
| **参数是否为最优值** | 所有参数值取自源码，`README` 与各文档中的「默认值」指的是**代码中的初值**，不代表实测调优结果 |
| **赛道表现** | 仓库中不含赛道测试数据、圈速、成绩或视频 |
| **引脚与实际接线是否一致** | 引脚定义取自源码，未与实物核对 |

### 4.1 关于「未启用」的说明

`main` 分支中元素识别的调用处于注释状态（见 README
的[第 9 节](../README.md#9-分支说明)）。文档中对该逻辑的描述来自代码本身的分析，
**不代表该逻辑经过运行验证**。`feature/adaptive-find-lines` 分支中这些调用是开启的，
但同样未经过本次整理的验证。
